## 1. Цель и описание проекта

Разработать консольный эмулятор оболочки UNIX-подобной операционной системы с виртуальной файловой системой (VFS). Эмулятор принимает команды в интерактивном режиме и из стартового скрипта. Работа с файлами и каталогами VFS выполняется **только в оперативной памяти**. Изменения прав доступа не записываются в исходный JSON.

Исходное задание: сборник практических работ № 1, вариант № 24, страницы 77–79 (РТУ МИРЭА, 2026).

## 2. Выполнение этапов

### Этап 1. REPL

Реализована консольная оболочка с приглашением `username@hostname:/path$`, содержащим реальные имя пользователя и имя компьютера. Парсер `shlex.split` корректно обрабатывает кавычки. Для ошибок предусмотрены сообщения о неизвестных командах, неправильном количестве аргументов, ошибках кавычек и некорректных путях. Команды `ls` и `cd` реализованы в полном объёме (вместо первоначальных заглушек), `exit` завершает сеанс.

### Этап 2. Конфигурация

Поддерживаются параметры командной строки:

| Параметр | Назначение |
|---|---|
| `--vfs ПУТЬ` | Путь к файлу виртуальной ФС |
| `--script ПУТЬ` | Путь к стартовому скрипту |
| `--config ПУТЬ` | Путь к JSON-конфигурации |

Файл `config.json` содержит ключи `vfs` и `script`. Параметры командной строки **приоритетнее** параметров JSON. При запуске выводятся итоговые значения параметров. Стартовый скрипт выполняется последовательно, отображает команды и результаты, останавливается при первой ошибке с указанием номера строки. Строки, начинающиеся с `#`, и пустые строки пропускаются.

### Этап 3. Виртуальная файловая система

Источник VFS — JSON-файл с полями `name` и `root`. Папки содержат словарь `children`, текстовые файлы хранят байты в `content_b64` (base64). Данные загружаются в оперативную память. Команда `vfs-info` показывает имя VFS и **SHA-256 исходных байтов JSON-файла**, полученный при загрузке. Если выполнить `chmod`, хеш останется исходным: физический файл не меняется.

Подготовлены 3 тестовых VFS: `minimal.json` (пустая), `files.json` (несколько файлов), `sample.json` (многоуровневая структура `/home/student/docs/data.txt`).

### Этап 4. Основные команды

| Команда | Описание | Пример |
|---|---|---|
| `ls [path]` | Список имён файлов и каталогов | `ls home` |
| `cd [path]` | Перейти в каталог (`cd` — в корень) | `cd home/student` |
| `whoami` | Вывести реального пользователя ОС | `whoami` |
| `tac <file>` | Вывести строки текстового файла в обратном порядке | `tac readme.txt` |
| `clear` | Очистить экран ANSI-последовательностью | `clear` |
| `exit` | Завершить работу | `exit` |
| `vfs-info` | Имя VFS и SHA-256 исходного JSON | `vfs-info` |

Для `tac` предусмотрено чтение только UTF-8 файлов. При попытке передать каталог или несуществующий путь выводится ошибка. Поддерживаются относительные и абсолютные пути, `.` и `..`.

### Этап 5. Дополнительная команда

`chmod <mode> <path>` — изменение режима доступа файла или каталога **в оперативной памяти**. Режим задаётся 3 или 4 восьмеричными цифрами, например `chmod 600 readme.txt`. Изменение сохраняется до завершения работы процесса и не затрагивает исходный JSON. Эмулятор хранит значение режима, но **не реализует настоящие проверки прав доступа** (этого нет среди требований варианта).

## 4. Установка и запуск

Нужен установленный **Python 3**. Сторонние зависимости не требуются. Открыть терминал **в папке `variant24`**.

**Windows PowerShell или CMD:**

```powershell
python src/emulator.py --vfs vfs/sample.json
```

Или запустить `run.bat` двойным щелчком (лучше из CMD, чтобы видеть вывод).

**С конфигурацией и стартовым скриптом:**

```powershell
python src/emulator.py --config config.json
```

**Проверка приоритета командной строки над JSON:**

```powershell
python src/emulator.py --config config.json --vfs vfs/files.json
```

**Запуск с разными источниками VFS:**

```powershell
python src/emulator.py --vfs vfs/minimal.json
python src/emulator.py --vfs vfs/files.json
python src/emulator.py --vfs vfs/sample.json
```

**Проверка остановки скрипта при ошибке:**

```powershell
python src/emulator.py --vfs vfs/sample.json --script scripts/errors.txt
```

Тестовые BAT-файлы: `scripts/test_config.bat`, `scripts/test_vfs.bat`, `scripts/test_script.bat`. Их следует запускать из Windows.

## 5. Пример интерактивной работы

Вместо `user@computer` будет показано реальное имя пользователя и имя ПК:

```text
user@computer:/$ ls
home
readme.txt
user@computer:/$ cd home/student/docs
user@computer:/home/student/docs$ ls
data.txt
user@computer:/home/student/docs$ tac data.txt
third
second
first
user@computer:/home/student/docs$ chmod 600 data.txt
user@computer:/home/student/docs$ vfs-info
Name: sample
SHA-256: <64 шестнадцатеричных символа>
user@computer:/home/student/docs$ invalid_command
Error: Unknown command: invalid_command
user@computer:/home/student/docs$ exit
```

Этот блок — **образец ожидаемого диалога**, а не скриншот проведённого интерактивного сеанса. Реальный хеш вычисляется программой из байтов `vfs/sample.json`.

## 7. Требования к репозиторию Git

В репозитории должны находиться папки `src`, `tests`, файлы `README.md`, `.gitignore`, `run.bat`. Не добавлять архивы проекта, `__pycache__`, `.pyc` и другие артефакты выполнения.

Пример команд первого коммита:

```powershell
git init
git add README.md .gitignore run.bat config.json src tests vfs scripts
git commit -m "feat(shell): implement variant 24 emulator"
```

По условию преподавателя **каждый из пяти этапов должен быть отражён отдельным осмысленным коммитом**. Для корректной поэтапной истории нужно добавлять соответствующие изменения и коммитить их после каждого этапа; один итоговый коммит из примера выше не заменяет эту историю. Не следует выдавать историю коммитов за уже созданную.
