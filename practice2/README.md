Урсу Никита Юрьевич, ИКБО-16-25.

Консольный инструмент строит граф зависимостей NuGet для заданной версии
пакета. Метаданные получает стандартными urllib и ElementTree через NuGet
Service Index, PackageBaseAddress и XML nuspec. Менеджер пакетов и сторонние
библиотеки для получения зависимостей в приложении не используются.

## Запуск на Windows

Требуются Python 3 с launcher py и Java. Выполните setup.bat для загрузки
официального PlantUML JAR. Затем запустите run.bat. На этом компьютере JAR
уже загружен в tools. Он исключён из Git как сторонний бинарный файл.

По умолчанию запускается учебный граф A–E.

~~~powershell
py -3 src/main.py examples/test.ini
py -3 src/main.py examples/newtonsoft.ini
py -3 src/main.py examples/serilog.ini
py -3 src/main.py examples/logging.ini
~~~

Рядом с результатом SVG сохраняется исходный текст PlantUML с расширением
puml. Откройте SVG браузером. Ключ PLANTUML_JAR в окружении позволяет указать
другое расположение JAR.

## Параметры INI

Все параметры находятся в секции analysis и обязательны.

| Параметр | Назначение |
|---|---|
| package | Имя пакета, в тестовом режиме большая латинская буква |
| repository | HTTPS URL NuGet v3 index либо путь к JSON графу |
| test_mode | true или false |
| version | Точная версия корневого пакета |
| output | Путь к итоговому SVG |
| max_depth | Неотрицательная глубина, 0 выводит только корень |
| exclude | Подстрока имени исключаемых зависимостей, пустая отключает фильтр |

Относительные пути разрешаются относительно INI. Фильтр не применяется
к заданному пользователем корню. Отсутствующий INI, обязательные ключи,
неверные имя, версия, режим, глубина, расширение и репозиторий дают ошибку.
Сетевые и XML ошибки также завершают программу с ненулевым кодом.

## Алгоритмы и функции

settings.read_settings проверяет параметры. NuGetRepository.dependencies
считывает прямые зависимости конкретной версии из nuspec. resolve выбирает
минимальную подходящую версию для ребра. Поддерживаются точные версии,
минимальные версии, открытые и закрытые интервалы. Floating versions
и полный алгоритм согласования конфликтующих ограничений NuGet не реализованы.

Целевая платформа для реальных пакетов — .NET Standard 2.0. Выбирается ближайшая
группа netstandard не выше 2.0, либо общая группа без платформы.
Неподдерживаемая группа вызывает понятную ошибку.

graph.build_graph использует стек DFS без рекурсии. Ключ узла содержит
имя и версию. Общий узел повторно раскрывается при нахождении более короткого
пути, чтобы ограничение глубины не теряло допустимые зависимости.
Циклы завершаются благодаря сохранению уже достигнутой глубины.

order.loading_order выполняет итеративный DFS с состояниями узлов.
Для ациклического графа зависимости стоят раньше потребителя.
При цикле выводятся обратные рёбра и предупреждение, что топологический
порядок невозможен. Полученный список в таком случае служит обходом графа.

visualize.plantuml_text присваивает узлам устойчивые псевдонимы.
visualize.render запускает локальный PlantUML с движком Smetana.
SVG генерируется самим PlantUML.

## Тестовые примеры

examples/minimal.json содержит один узел.
examples/diamond.json содержит общий узел D на двух ветвях.
examples/cycle.json содержит цикл A → B → C → A.
Для смены графа укажите нужный JSON в копии examples/test.ini.
Поставьте max_depth = 1 для прямых зависимостей, exclude = B для фильтра.

## Проверка

~~~powershell
py -3 -m unittest discover -s tests -v
~~~

Проверяются порядок, цикл, глубина 0, фильтрация, интервалы версий,
PlantUML и ошибки конфигурации.

Приложение является интерпретируемым и не требует сборки.

## Сравнение со штатным инструментом

Фактическое сравнение с dotnet restore для трёх пакетов сохранено
в COMPARISON.md. Тест compare_native.py выполняет restore только для
независимой проверки, основной инструмент его не вызывает.

~~~powershell
py -3 tests/compare_native.py C:/path/to/dotnet.exe C:/temp/nuget-compare
~~~

Штатный NuGet строит согласованный граф с единой выбранной версией
пакета и дополнительными зависимостями платформы. Учебный граф показывает
версии отдельных ветвей и ограничен max_depth. Эти причины объясняют
расхождения состава узлов и порядка.
dotnet CLI предоставляет machine-readable граф project.assets.json,
а собственного экспорта SVG не имеет. Сравнение выполнено с этим
штатным графом, отдельный сторонний визуализатор NuGet не использовался.
